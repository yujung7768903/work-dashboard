## 4. 판정 기준

발화 하나를 다음 순서로 판정함.

| 단계 | 조건 | 처리 |
| --- | --- | --- |
| 1 | 어시스턴트 응답 이후의 발화인가 | 아니면 제외 (첫 지시는 수정이 아님) |
| 2 | 이미 나온 산출물 또는 방금 한 행동을 고치라는 지시인가 | 아니면 제외 (질문·신규 요청·커밋 요청) |
| 3 | 실행 실패·빌드 에러·명세 위반 때문인가 | 맞으면 `에러 기인` |
| 4 | 그 외 취향·판단에 따른 것 | `선호 기반` |

카테고리 배정.

| 카테고리 | 포함 대상 |
| --- | --- |
| 디자인 | 레이아웃, 색, 간격, 애니메이션, 컴포넌트 형태, 화면 흐름 |
| 개발 | 코드 구조, 네이밍, API·DB 설계, 스킬·플러그인 동작 |
| 인프라 | 로컬 환경, 단축키, 창 관리, 배포·계정 설정 |
| 기타 | 문서 형식·말투, 작업 범위·순서, 검증 방식, 산출물 형식 |

경계 사례 처리.

| 사례 | 처리 | 이유 |
| --- | --- | --- |
| "동작은 하는데 비효율적이다" | 선호 기반 | 실패가 아니라 판단 |
| "의도치 않은 요소가 보인다" (회색 선, 잘못된 그래프) | 에러 기인 | 객관적 결함 |
| "시킨 것과 다르게 했다" | 선호 기반 | 지시 위반은 선호의 강한 형태 |
| 한 발화에 지시 여러 개 | 1건 | 발화 단위로 셈 |
